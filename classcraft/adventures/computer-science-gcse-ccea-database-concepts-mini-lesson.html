Databases · basic concepts

What is a database?

A database is an organised, structured store of data. In CCEA you need the key vocabulary:

  • Table — a set of data about one type of thing (e.g. Students).
  • Record — a row holding all the data about one item (one student).
  • Field — a column holding one piece of data (one attribute, e.g. Name).
  • Key field — a field used to identify records; the primary key uniquely identifies each record.
  • Query — a request to search/extract data that meets set conditions.
  • Form — an on-screen layout used to enter or view a record.
  • Report — a formatted way of printing/presenting selected data.
  • Macro — stored steps that automate a repeated task.
  • Relationship — a link between tables; importing data brings in data from another source.

Structure to nail: a table is made of records (rows), and each record is made of fields (columns). So field ⊂ record ⊂ table.

Databases · flat file vs relational

Flat file vs relational database

A flat file database uses a single table. If the same details are repeated in many records, this causes data duplication (redundancy) and risks inconsistency when only some copies are updated.

A relational database uses several linked tables. Storing repeated data once and linking to it reduces data redundancy and keeps data consistent. Tables are joined using relationships (often one-to-many).

Watch out: a relational database's main advantage is reduced data redundancy (and better consistency) — not that it holds "more" data. The link between two tables is made with keys.

Databases · primary & foreign keys

Primary & foreign keys

Keys are the fields that identify records and join tables:

  • Primary key — a field that uniquely identifies each record in a table. It must have no duplicates and no blank (null) values (e.g. StudentID).
  • Foreign key — a field in one table that refers to the primary key of another table. This is what creates the link (relationship) between the two tables.

Key rule: a primary key is unique per table; a foreign key is a copy of another table's primary key placed in a second table to join them.

Databases · data types & validation

Data types & validation checks

When you build a database you choose a data type for each field so the data is stored correctly:

  • Numeric — integer (whole, e.g. 15) or real (decimal, e.g. 3.75).
  • Date/Time · Character · String/Text · Boolean (yes/no, true/false).

Databases · queries & SQL

Queries & simple SQL

A query extracts records that meet set conditions. In SQL a simple query has three parts:

SELECT field(s) FROM table WHERE conditionSELECT = which fields · FROM = which table · WHERE = the condition to filter rows

You build conditions with the operators <, >, =, <=, >= and the logical operators AND, OR and BETWEEN.

Reading a query

SELECT * FROM Pupils WHERE Age BETWEEN 12 AND 15;

This returns every field (*) of each pupil whose Age is 12, 13, 14 or 15 (BETWEEN is inclusive of both ends).

Key: WHERE is the keyword that filters which rows/records are returned. BETWEEN a AND b includes both a and b.

Recap

The big ideas to know

Structure: table → records (rows) → fields (columns)

Terms: query · form · report · macro · relationship · importing data

Flat file vs relational: flat file = one table, causes redundancy; relational = linked tables, reduces redundancy

Keys: primary key = unique per record (no duplicates/nulls); foreign key = links to another table's primary key

Data types & validation: integer/real, date, text, Boolean; checks = presence, length, type, format, range

SQL: SELECT fields · FROM table · WHERE condition; operators < > = <= >= AND OR BETWEEN
