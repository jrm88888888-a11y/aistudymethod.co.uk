Data & variables · storage

Variables and constants

A program needs to store data while it runs. Two named stores do this:

  • A variable is a named store whose value can change while the program runs (e.g. a running score that goes up).
  • A constant is a named store whose value is fixed and cannot change once set (e.g. VAT = 0.20 or PI = 3.14159).

Why use a constant? It makes code clearer and safer — if a fixed value like a tax rate appears once by name, you never risk accidentally overwriting it, and you only change it in one place.

Data & variables · data types

Data types

Every stored value has a data type that tells the computer what kind of data it is and what you can do with it:

  • Integer — whole numbers only, e.g. a count of items or a score.
  • Real / float — numbers with a decimal part, e.g. a price or a measurement.
  • Character — a single letter, digit or symbol; string — a sequence of characters (text like a name).
  • Boolean — one of two values, True or False (great for a yes/no flag).
  • Date/time — a calendar date or a time value.

Constructs · sequence, selection, iteration

The three programming constructs

Almost any program is built from just three ways of controlling the flow:

  • Sequence — instructions carried out one after another, in the order written.
  • Selection — the program makes a decision using IF … ELSE and only runs some code when a condition is met.
  • Iteration — a loop repeats a block of code: a count-controlled loop (FOR) repeats a set number of times; a condition-controlled loop (WHILE) repeats until a condition changes.

Operators · arithmetic, relational, Boolean

Operators

Operators let a program calculate and compare. There are three families:

  • Arithmetic — +  -  *  /, plus MOD (remainder of a division) and DIV (whole-number quotient).
  • Relational / comparison — =  <  >  <=  >=  <> (or != for "not equal"). These give a Boolean result.
  • Boolean / logical — AND, OR, NOT combine conditions.
17 MOD 5 = 2  ·  17 DIV 5 = 3MOD gives the remainder (17 = 3×5 + 2); DIV gives the whole-number quotient (3 lots of 5)

Watch out: = in a condition means "is equal to" (a comparison), which is different from assigning a value to a variable. MOD and DIV work together: 17 = 5 × 3 (DIV) + 2 (MOD).

Arrays · one-dimensional

One-dimensional arrays

An array is an ordered list of elements stored under one name. Each element is reached by its index (its position number).

Important — count from zero! In this lesson (as in most CCEA pseudocode contexts) the first element is index 0. So an array of 5 elements has indices 0, 1, 2, 3, 4 — the last index is one less than the length.

Subprograms · string manipulation

Subprograms & string handling

A subprogram is a named, reusable block of code — a user-defined function, procedure or method. You call it whenever you need it, and it can take parameters (inputs). Subprograms reduce repetition and make code easier to read and maintain.

Programs often work on text. Common string manipulation operations include:

  • Concatenation — joining two strings together, e.g. "Aoife" + " Murphy" → "Aoife Murphy".
  • Splitting — breaking a string into parts (e.g. splitting a full name at the space).
  • Character searching — finding whether/where a character occurs.
  • Substring searching — finding a shorter string inside a longer one.

Key idea: writing a subprogram once and calling it many times is far better than copying the same code repeatedly — one fix updates every use.

Validation · checking input

Validation

Validation checks that data entered is sensible and allowed before the program uses it. Note: it checks data is reasonable, not that it is actually correct (a valid date of birth could still be the wrong one).

  • Presence check — a required field is not left blank.
  • Length check — the number of characters is within allowed limits (e.g. a password is at least 8 characters).
  • Type check — the data is of the right type (e.g. an age is a number, not letters).
  • Format check — the data follows the right pattern (e.g. a postcode or email layout).
  • Range check — a number lies between allowed limits (e.g. a month is 1–12).

Testing · error types

Testing & error types

We test programs to find and fix errors. There are three main kinds:

  • Syntax error — breaks the rules of the language (e.g. a missing bracket), so the program won't run or compile.
  • Runtime / execution error — the program runs but then crashes, e.g. dividing by zero.
  • Logic error — the program runs without crashing but gives the wrong result (e.g. using + where you needed *).

Nail this distinction: a logic error is the sneaky one — nothing crashes, so the only way to spot it is to check the output against what you expected. Use extreme (boundary) test data to catch off-by-one mistakes.
