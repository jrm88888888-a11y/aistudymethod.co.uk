Data representation

Computers only store binary — patterns of 0s and 1s. This mini-lesson shows how those bits are used to represent numbers, text and images, and sound, and why we compress data to save space.

Data vs information

Data and information

These two words sound the same but mean different things in Computer Science:

  • Data is raw facts and figures with no context — e.g. the number 37 on its own, or the letters H E L L O.
  • Information is data that has been processed and given meaning — e.g. "the temperature is 37 °C" or "the message says HELLO".

Simple way to remember it: data goes in, the computer processes it, and information comes out. Information is data with context that lets us make a decision.

Units of storage

Bits, nibbles and bytes

The smallest piece of data is a bit (binary digit) — a single 0 or 1. Bits are grouped into larger units:

  • 1 nibble = 4 bits (half a byte).
  • 1 byte = 8 bits — enough to store one ASCII character.
  • Bigger units follow: kilobyte (KB) → megabyte (MB) → gigabyte (GB) → terabyte (TB), each about 1000× (10³) larger than the last.

Exam-critical facts: 1 nibble = 4 bits and 1 byte = 8 bits. (Traditionally 1 KB is written as 1024 bytes, but you just need to know the order of the units and that each is ~1000× the last.)

Number systems

Denary, binary & hexadecimal

We use three number systems in Computer Science, each with a different base (how many digits it uses):

  • Denary — base 10. Our everyday numbers, digits 0–9.
  • Binary — base 2. Only 0 and 1 — what the computer actually stores.
  • Hexadecimal — base 16. Digits 0–9 then A–F (A=10 … F=15). A short, human-friendly way to write binary.

Key link: one hex digit = one nibble = 4 binary bits. So one byte (8 bits) is written as exactly two hex digits. The highest byte value is denary 255 = binary 11111111 = hex FF.

Binary addition · overflow

Binary addition & overflow

Binary addition works like denary, but you carry whenever a column reaches 2 (because 1 + 1 = 10 in binary):

Worked example — adding two bytes

  00001100  (12)

+ 00000101  (5)

= 00010001  (17) ✓ fits in 8 bits

Overflow happens when the answer needs a 9th bit — it is too big to fit in the 8 bits available. In one byte the biggest value is 255, so any total above 255 overflows and the extra carry is lost.

Remember: overflow means the result is too large for the number of bits available (here, more than 255 in one byte), so the answer is wrong because the carry bit cannot be stored.

Text · character sets

ASCII & Unicode

Every character (letter, digit, symbol) is stored as a binary number using a character set — an agreed code that maps characters to numbers.

  • ASCII — the classic 7-bit code, so it can represent 2⁷ = 128 different characters (letters, digits, punctuation). An 8-bit extended version gives 2⁸ = 256 characters.
  • Unicode — a much larger set that uses more bits, so it can represent far more characters: other alphabets (Arabic, Chinese, etc.), symbols and even emoji.

Watch out: more characters need more bits. 7-bit ASCII = 128, 8-bit = 256; Unicode uses even more bits to cover every writing system in the world.

Images · bitmap vs vector

Representing images

A bitmap image is made of tiny squares called pixels. Each pixel's colour is stored as a binary number. The resolution is the number of pixels — more pixels = more detail = a larger file size.

  • Bitmap graphics store the colour of every pixel in a grid. Zoom in too far and you see the squares — they become blocky/pixelated.
  • Vector graphics store shapes as mathematical objects (lines, curves, coordinates). They can be scaled to any size without losing quality.

Key difference: bitmaps are made of pixels and are resolution-dependent; vectors are made of maths and are scalable. Photos are usually bitmaps; logos are often vectors.

Sound · sampling

Representing sound

Sound is naturally analogue (a smooth wave). To store it, a computer takes regular samples of the wave and records each as a binary number — this is analogue-to-digital conversion.

Three factors affect the quality (and the file size) of digital sound:

  • Sample rate — how many samples are taken per second. Higher = more accurate wave = bigger file.
  • Bit depth — how many bits store each sample. More bits = finer detail per sample.
  • Bit rate — the number of bits used per second (roughly sample rate × bit depth).

Trade-off: higher sample rate and bit depth give better quality but a larger file size. That is one reason we compress audio.

Compression

The need for compression

Compression makes a file smaller — it uses fewer bits to store the same data. This matters for lots of reasons:

  • Less storage space is used on the disk or device.
  • Files transfer faster over a network (less to download or upload), and use less bandwidth/data.
  • More files fit in the same space (e.g. more songs on a phone).

In short: we compress data to save storage space, make transfers faster, and use less bandwidth.

The big ideas to know

Data vs information: data = raw facts; information = data processed & given meaning

Units: bit → nibble (4 bits) → byte (8 bits) → KB → MB → GB → TB

Number systems: denary (base 10) · binary (base 2) · hex (base 16); 1 hex digit = 1 nibble = 4 bits; FF = 255 = 11111111

Overflow: answer needs a 9th bit (over 255 in one byte) so the carry is lost

Characters: ASCII (7-bit = 128, 8-bit = 256) · Unicode = far more (world alphabets & emoji)

Images: bitmap = pixels (resolution-dependent) · vector = maths (scalable)

Sound: analogue → digital by sampling; sample rate · bit depth · bit rate affect quality

Compression: smaller files → less storage & faster transfer
