Computational thinking

Abstraction & decomposition

Before we write an algorithm we think about the problem. CCEA highlights two key skills:

  • Abstraction — removing or hiding unnecessary detail so we focus only on what matters. A Tube map ignores real distances and streets; it keeps only the stations and connections you need.
  • Decomposition — breaking a problem into smaller sub-problems that are easier to solve. "Make breakfast" becomes: boil kettle, make toast, pour juice.

Don't mix them up: abstraction is about hiding detail; decomposition is about splitting the problem up. Both make a hard problem manageable, but they are different ideas.

Representing algorithms

What is an algorithm?

An algorithm is a precise, step-by-step sequence of instructions that solves a problem or completes a task. We can write the same algorithm three ways:

  • Flow diagram (flowchart) — boxes and arrows showing the flow.
  • Pseudo-code — code-like English that isn't tied to one language.
  • Structured English — plain numbered steps in ordinary words.

Searching · linear & binary

Linear search & binary search

A search algorithm finds an item in a list. There are two you must know:

  • Linear search — checks each item in turn from the start until the target is found or the end is reached. Works on any list (it does not need to be sorted). Worst case it checks all n items.
  • Binary search — requires a sorted list. It checks the middle item, then discards half the list each time, repeating on the remaining half. Much faster on large sorted lists.

Key difference: binary search only works on a sorted list; linear search works on any list but can be slow because it may check every item.

Sorting · bubble & insertion

Bubble sort & insertion sort

A sort algorithm puts a list into order. Two are on the CCEA spec:

  • Bubble sort — repeatedly steps through the list, comparing adjacent pairs and swapping them if they are in the wrong order. The largest value "bubbles" to the end each pass; it repeats until a pass makes no swaps.
  • Insertion sort — builds a sorted section one item at a time, taking each new item and inserting it into its correct place among the items already sorted.

Watch out: bubble sort only ever compares adjacent items. Insertion sort instead slides each new item back into the already-sorted part of the list.

Searching · counting comparisons

Counting comparisons

Exam questions often ask how many comparisons a search makes. Count carefully — one comparison each time you look at an item.

binary search: max comparisons = ⌈log₂ n⌉each comparison roughly halves what's left, so a big list needs surprisingly few checks
Worked example — binary search

A sorted list has 16 items. Max comparisons = ⌈log₂ 16⌉ = 4 (16 → 8 → 4 → 2 → 1).

Trace tables

Trace tables

A trace table is a table used to dry-run an algorithm by hand. You record the value of each variable at each step, which lets you check the algorithm works and helps you find errors.

Exam tip: add a new row every time a variable changes. Don't overwrite — keeping every step is what makes the bug visible.

Sorting · tracing swaps

Tracing a bubble sort pass

To count swaps in a bubble sort, work left to right comparing each adjacent pair. Let's trace the first pass on [5, 3, 8, 1]:

First pass on [5, 3, 8, 1]

Compare 5,3 → 5>3 so swap → [3, 5, 8, 1]

Compare 5,8 → 5<8 so no swap → [3, 5, 8, 1]

Compare 8,1 → 8>1 so swap → [3, 5, 1, 8]

2 swaps in the first pass; 8 has bubbled to the end.

Remember: after one full pass the largest value is guaranteed to be in its final place at the end. Bubble sort keeps passing until a pass makes no swaps at all.

Representing algorithms

Flowchart symbols in detail

Each flowchart shape has a fixed meaning — CCEA expects you to recognise all four:

  • Terminator (rounded box) — marks START and STOP.
  • Process (rectangle) — an action or calculation, e.g. total = total + 1.
  • Decision (diamond) — a yes/no question that branches the flow.
  • Input/output (parallelogram) — reading data in or displaying it out.

Pseudo-code and structured English describe the same logic in words rather than shapes — useful when a flowchart would get too big.

Exam tip: a very common mark is spotting that a diamond is a decision. If a symbol has two arrows leaving it (yes/no), it must be a decision.

Sorting · insertion sort

Insertion sort up close

Insertion sort is like sorting playing cards in your hand. You keep a sorted section at the front and take each new card, sliding it back until it sits in the right place.

  • Start: the first item is trivially "sorted".
  • Take the next item and compare it back through the sorted section.
  • Shift bigger items right, then insert the new item into the gap.
  • Repeat until every item has been inserted.

Contrast: bubble sort keeps sweeping the whole list swapping neighbours; insertion sort grows one sorted section and inserts into it. Both end with the list in order.

Choosing an algorithm

Which algorithm should I use?

Choosing the right algorithm depends on the data:

  • List unsorted and you must search it → use a linear search (binary won't work).
  • List sorted and large → use a binary search for speed.
  • Need the list in order → use a sort (bubble is simple; insertion is often faster on nearly-sorted data).

Big idea: binary search and sorting go hand in hand — you often sort first so you can then binary search quickly and repeatedly.
